## 1. Executive Assessment

The plan is architecturally sound in its skeleton: policy registry with fail-closed validation, pure-function engine behind `EvaluateFor`, indexed-data-only analyzer inside the existing 30 s deadline, golden corpus for v1 byte-identity, additive-only wire contract. The author did real scouting — `persistFailed`'s hardcoded `PolicyV1` (`service.go:310,340`), the `BulkMatchLabels` reuse, `IS DISTINCT FROM` NULL semantics, and big.Int floor math are all correctly identified and reasoned about.

However, verification against the actual code surfaced **one MUST-NOT-class defect** and **one coverage-honesty blind spot** the plan does not address, plus a cluster of smaller gaps:

1. **F1 (blocking)**: The flat-21 provider-source rule has no direction gate, and the *only* provider emitting `Exposures` today — PublicAML — emits **outbound** items (`Direction:"outbound"`) whose `Counterparty` is a parseable EVM address. As written, v1.1 scores candidate→risky outbound flows at +21 — a direct violation of the prompt's MUST-NOT and proposal §3.2/§4. v1 already mis-scores these at +7, but v1 is frozen; v1.1 amplifies the error to +21.
2. **F2 (blocking)**: The depth-1 receiver check reads `to_wallet_id ∈ source_ids` — rows that exist **only when the source wallet was itself indexed** (lazy per-wallet indexing; `EnsureIndexed` is invoked only from tracing hop-0/hop-1, the transactions endpoint, and warmindex — never screening). The plan reads the **candidate's** index state only ("1 index-state read total"), so `coverage:"complete"` can be emitted while every receiver check was unevaluatable. Chain-taint is silently dead code for unindexed sources *and* dishonest about it.
3. **F3**: Coverage semantics under-specify the status vocabulary — `'indexing'` rows unhandled, `'stale'` has no wired horizon (`FreshTTL` lives in `transaction.Config`, not `screening.Deps`).
4. **F4**: The service-classified-candidate gate couples to `KindLabel` findings, requiring `include_labels=true` *and* usable labels — an EXCHANGE-labeled candidate screened with `include_labels=false` bypasses §3.4 suppression entirely.
5. **F5**: Several additive fields need `,omitempty` to keep v1 wire output byte-identical; the plan asserts hash-stability without the mechanism that makes it true.
6. **F6**: `VerificationStatus=verified` stamped on findings backed by `reported`/`disputed` labels — reported→verified inflation; and `disputed` tainting at all contradicts the engine's own `disputed→0` treatment.

None are fatal to the design; all fixable inside the existing phase structure.

## 3. Phase-by-Phase Critique

### Phase 1 — Policy registry, config + request plumbing: **ACCEPTED with one required fix**

Sound: registry-in-one-file, `KnownPolicy` consumed by config/handler/`EvaluateFor`, pointer-typed `OptionsIn.PolicyVersion`, `persistFailed` stamping resolved policy.

Spell `,omitempty` in the phase.
- Minor: write explicitly that the 400 validation precedes `requestHash`/claim insert (`handler.go:94-102` region).

### Phase 2 — sqlc queries + price/meaningful evaluator: **CHALLENGED**

Sound: query mirrors `ListWalletEdges` join pattern (`transactions.sql:74-85`) and correctly adds the `'confirmed'` filter `ListWalletEdges` lacks; big.Int product compare is exactly right (boundary math checks: 0.0333… ETH × $3000 = $100 exact); env-overlay validation fail-closed.

- **F2a (required)**: `ListWalletIndexStates` takes a single `wallet_id`; analyzer budgets "1 index-state read" → reads the **candidate only**. Change to `WHERE network_id=$1 AND wallet_id = ANY($2::bigint[])` — one query covers candidate + all sources, still 1 round trip.
- **F2b (required)**: Depth-2 sender set unbounded — the receiver-check scan admits up to 5000 rows → up to ~5000 distinct senders feed the second bulk check. Add a policy-constant cap on distinct depth-2 senders evaluated; overflow → coverage partial.
- **F3a**: "stale" named as a partial-coverage trigger but the horizon is nowhere defined or wired. The codebase derives `Stale = indexed_at older than FreshTTL` (`transaction/service.go` `fillFromState` ~`:706`; `cfg.IndexingFreshTTL`, `config.go:246`).
